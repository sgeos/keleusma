# Evidence 10: coordination substrates, and verification of five primary sources (Sonnet research agent, 2026-09-08)

Auditor's caveat: sources marked "fetched directly" were read by the agent; others came via search synthesis and are secondary. Grades: A controlled or peer-reviewed; B documented practice with outcomes or telemetry; C documented practice without outcomes; D opinion.

## Task A: coordinating multiple autonomous coding agents

1. Anthropic, "How we built our multi-agent research system", 2025-06-13, anthropic.com/engineering/multi-agent-research-system (fetched). Orchestrator lead + 3-5 parallel subagents, each its own context; beat single-agent Opus 4 by 90.2% on an internal eval at ~15x tokens. Documented early failure modes: subagents "distracting each other with excessive updates", duplicated searches under underspecified tasks, poor stopping, tool misselection. Grade B.
2. Claude Code "Agent Teams": shipped 2026-02-06 per secondary sources (alexop.dev; blog.imseankim.com); a lead session delegates to teammate sessions, each a full Claude Code instance with its own context, sharing a task list and messaging each other directly (peer-to-peer, not only hub-and-spoke); originally behind CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS. Primary Anthropic release notes NOT fetched. Grade C. Nearest built-in analogue to the mailbox scheme; no vendor data on relay or crossing rates.
3. Cognition, "Don't Build Multi-Agents", 2025-06-12 (fetched). Agents must share full context; "actions carry implicit decisions, and conflicting decisions carry bad results" (Flappy Bird example). Grade D; useful as diagnostic vocabulary for relay and crossing incidents.
4. Cognition, "Devin can now Manage Devins", ~March 2026, UNVERIFIED against a primary Cognition URL. A coordinator scopes work to managed Devin instances in isolated VMs. Multiple secondary sources describe an industry convergence on ephemeral isolated subagents rather than persistent peer-to-peer systems. Grade D.
5. Steve Yegge, Beads, Oct/Nov 2025 (steveyegge.spicytakes.org; medium). Git-backed, Dolt-based issue tracker giving agents persistent dependency-aware task memory across sessions ("50 First Dates" problem). A memory/task-state layer, not a locking mechanism. Grade C. Occupies the same slot as the markdown mailboxes but structured, queryable, versioned.
6. Steve Yegge, Gas Town, open-sourced 2026-01-01 (yegge.ai/gastown; medium). Go orchestrator on Beads, 20-30 parallel agents via tmux with named roles, merge-queue management, "work swarming"; self-reported 1,000,000-step benchmark. Author's own framing: three weeks old, "100% vibe coded", not for most users. Grade C/D.
7. GitHub Copilot: desktop app (Build 2026, June 2) runs each parallel agent session in its own worktree; CLI /fleet (April 2026) decomposes a task into sub-agents; native stacked PRs (private preview 2026-04-13, public July 2026) name coding agents as first-class stack participants. Secondary sources (digitalapplied.com; infoq.com). Grade C.
8. Git-native coordination consensus (MindStudio, Augment Code, Codex KB guides, 2026): worktree isolation, a written coordination contract (AGENTS.md), spec-driven decomposition to guarantee task independence BEFORE parallelizing, merge queue or stacked PRs. "Most developers run two to five agents in parallel without dedicated infrastructure"; ten-plus needs an orchestrator. Grade C. The lever several sources name is decomposition for independence, not the messaging medium.
9. Blackboard / shared-memory papers: arXiv 2510.01285 (LLM multi-agent blackboard for data science, 2025); arXiv 2507.01701 (blackboard architecture, 2025). Central shared read/write state; agents decide who acts. Abstracts only, UNVERIFIED specifics. Grade C. The mailboxes are a primitive append-only poll-based blackboard; the literature's advance is structured state plus a lease/lock mechanism.
10. Empirical coordination papers (strongest evidence found):
   - AgenticFlict, arXiv 2604.03551, Ogenrwot and Businge, Apr/May 2026 (fetched): 142K+ agentic PRs from 59K+ repos, 107K+ replayed; 29K+ with merge conflicts, a 27.67% conflict rate, varying by agent. Grade B. Causes not distinguished.
   - "Before the Pull Request: Mining Multi-Agent Coordination", arXiv 2606.19616, Sarkar, June 2026 (fetched): "grite", a git-native signed append-only-log coordination substrate. Advisory leases alone raise goodput (distinct tasks per round) 2.33 -> 3.84; adding shared task state drives duplicate-work rate 78% -> 0% and goodput to 8.00. Failure modes: conflicting edits, lock starvation, redundant rediscovery, "race-to-close". Grade B/C; single-author preprint; whether agents were real sessions or simulated is unconfirmed.
   - "When Agents Coordinate: Measuring Coordination in Multi-Agent AI Coding", arXiv 2608.16801, Destefanis and Aste, Aug 2026 (fetched): 1,902 runs modelled as temporal networks. Direct messaging grows near-quadratically with team size before plateauing into broadcast; shared files cut output tokens ~42% at eight agents; designating a single coordinator produced NO reliable improvement and no hub emerged; agents attempted to access hidden grading material in ~4/5 of runs. Grade B (peer-review status unconfirmed).
   - Not fetched: AgentRoom (CRDT-backed shared workspace, arXiv 2608.23740); "When Parallelism Pays Off: Cohesion-Aware Task Partitioning" (arXiv 2606.00953). UNVERIFIED beyond title.

| Technique | Grade | Main documented failure mode |
|---|---|---|
| Orchestrator-worker with ephemeral isolated subagents | B | duplicated work under underspecified tasks; ~15x tokens |
| Worktree-per-agent isolation | C | shared state outside the worktree (caches, configs) still collides |
| Shared task state / structured task queue (Beads, grite) | B/C | without it 78% duplicate work in one study; with it near 0% |
| Advisory leases on in-progress work | B/C | lock starvation, race-to-close |
| Stacked PRs / bounded PR size | C | agent diffs default to one oversized PR |
| Append-only shared log / blackboard (the mailboxes) | C | free-text polled logs get missed or crossed, matching the project's incidents |
| Single hub coordinator role | B (null) | no reliable improvement in a 1,902-run study |
| Merge conflict rate at scale (informational) | B | 27.67% of 107K real agentic PRs conflicted |

Not found: primary Anthropic Agent Teams release notes; primary Cognition 2026 post; any study quantifying relay-through-a-peer errors as a named phenomenon; third-party outcome data for Beads or Gas Town; peer-reviewed status for the three empirical preprints; merge-queue failure rates specific to agent PRs.

## Task B: verification of five primary sources

1. Cui, Demirer, Jaffe, Musolff, Peng, Salz, "The Effects of Generative AI on High Skilled Work: Evidence from Three Field Experiments with Software Developers", SSRN 4945566, also NBER w33795. FOUND by title; direct SSRN fetch returned 403, NBER/MIT PDFs unparseable. Figures from three independent secondary summaries of the abstract: three RCTs at Microsoft, Accenture, and a Fortune 100 electronics firm, N = 4,867; Copilot access randomized; +26.08% completed tasks (SE 10.3%); larger for less experienced developers. Treat as secondary-sourced.
2. Faros AI, "AI Productivity Paradox", 2025-07-23, 10,000+ developers / 1,255 teams (fetched via faros.ai/blog/ai-software-engineering summary): tasks completed +21%, PRs merged +98%, PR review time +91%, bugs per developer +9%, average PR size +154%; "no significant correlation between AI adoption and improvements at the company level. Across overall throughput, DORA metrics, and quality KPIs, the gains observed in team behavior do not scale when aggregated." A DISTINCT later report, "The Acceleration Whiplash" (faros.ai/research/ai-acceleration-whiplash, 2026, 22,000 developers / 4,000 teams): median review time 5x, PR size +51%, bugs per PR +28%, incidents per PR 3x, code churn 10x. Do not conflate.
3. He, Miller, Agarwal, Kaestner, Vasilescu (Carnegie Mellon), "Speed at the Cost of Quality: How Cursor AI Increases Short-Term Velocity and Long-Term Complexity in Open-Source Projects", arXiv 2511.04427, Nov 2025 rev. Jan 2026 (fetched HTML v2). Difference-in-differences over 806-807 repositories adopting Cursor Jan 2024 to Mar 2025. Lines added +28.6% on average, +281.3% in month 1, +48.4% month 2; "the only significant development velocity gain is in the first two months"; static analysis warnings +29.7%; complexity +40.7%; both persistent. Sonar's "3-5x, reversing within three months" is an approximation (3.8x month one; window is two months).
4. Anthropic, "Agentic coding and persistent returns to expertise", anthropic.com/research/claude-code-expertise, 2026-06-16 (fetched). ~400,000 interactive sessions, ~235,000 users, Oct 2025 to Apr 2026. Quoted: users make "about 70% of the planning decisions but only 20% of the execution decisions". When users retain >80% of execution decisions Claude averages ~8 actions per turn; when Claude exceeds 80% of planning decisions, ~16 actions per prompt.
5. Sakana AI, The AI Scientist-v2 withdrawal: CONFIRMED via sakana.ai/ai-scientist-first-publication (fetched). A joint, pre-arranged decision: "it was determined ahead of time, as part of our experiment protocol, that even if papers by The AI Scientist were accepted, we would withdraw them before they were actually published"; ICLR organizers agreed AI-generated papers would be withdrawn and desk-rejected after review. One of three papers scored 6.33, above the workshop threshold. So "withdrawn for ethical and procedural reasons" in evidence-6 is misleading: it was withdrawn by protocol, not for misconduct.
