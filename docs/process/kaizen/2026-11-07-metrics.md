# Footprint Tracking and the Project's Metrics, 2026-11-07

> **Navigation**: [Kaizen](./README.md) | [Process](../README.md)

The operator asked on 2026-11-07 for the virtual machine's footprint to be tracked rather
than measured once, suggested an autogenerated file overwritten by the build so that users
have figures for their exact build, and asked for the key performance indicators and other
metrics suited to a project like this one. This record gives the tracking that was built,
why it is shaped as it is, the first figures, and the metrics.

## The footprint tracking

**What exists.** `footprint/` is a detached package, like `fuzz/`, that builds a bare-metal
image for the Cortex-M55 target, `thumbv8m.main-none-eabihf`, the core of the board the
RTOS example targets. Built without features it is the baseline: an entry point, a bump
allocator and a panic handler. Built with the probe, it loads a module and calls its entry
point. `scripts/footprint.sh` builds the baseline and each configuration, reads the
sections with `llvm-size`, and reports each configuration's flash and static RAM above the
baseline. Every run overwrites `footprint/target/footprint.json` with the figures, the
commit, whether the tree was clean, and the toolchain, so the file always describes the
build that produced it. `--check` fails when a configuration exceeds its ceiling in
`footprint/budget.tsv`, and `--features` measures a custom configuration as well. The CI
`footprint` job runs the check on every full run, writes the table to the job summary and
keeps the JSON as an artifact.

**Why not a file written by `cargo build` itself.** A build script runs before the code is
compiled and linked, so it cannot see the image, and a library cannot know the size of the
program that embeds it, which depends on that program's code, features, profile and target.
A build script that wrote into the source tree would also dirty every checkout and fail
`cargo publish`'s verification of the packaged crate. The measurement is therefore its own
build of a fixed reference program, which is the closest reproducible stand-in for an
embedder, and its output file is overwritten on every run as the operator proposed.

**Exact figures for a user's build** come in two parts.

- A user who selects other runtime features passes them with `--features`, and the probe
  reports that configuration on the same baseline.
- What can be known at compile time of the library, its enabled features, the `Value` slot
  size, the word and address widths, the opcode count and the bytecode version, could be
  generated by the crate's own build script into its output directory and exposed as a
  constant, so that a user's binary carries a record of exactly what it was built with. That
  is a change to the shipping crate's public interface, which is the V0.2.X line's to make,
  and it is proposed to that line rather than made here.

**Ceilings and history.** The ceilings sit 5 percent above the first measurement. A change
that needs more raises its ceiling in the same pull request, so growth is reviewed rather
than discovered. The history lives in the CI artifacts and, at each release, in the release
record, rather than in a tracked file rewritten by every merge, which would make every open
pull request conflict there as `CHANGELOG.md` once did.

## The first figures

At commit `a2cf8ada` with rustc 1.92.0, release profile, `opt-level = "s"`, fat link-time
optimization, one codegen unit, and `panic = "abort"`.

| Configuration | Runtime features | Flash above baseline | Static RAM above baseline |
|---|---|---|---|
| `vm-trusted` | none, loading under trust | 192,772 bytes | 0 |
| `vm-verify` | `verify` | 246,436 bytes | 0 |
| `vm-verify-floats` | `verify`, `floats` | 260,836 bytes | 0 |
| `vm-verify-floats-text` | `verify`, `floats`, `text` | 261,032 bytes | 0 |

**Inference.** The load-time verifier costs about 54 KB, floating point about 14 KB and text
almost nothing above that. About 190 KB for the interpreter alone is large for a
flash-limited part, and it is the figure most worth reducing, since the embedded target is
the project's stated market. The figures cover one call pattern, loading a module and
calling its entry point. A host that registers natives, resumes streams or swaps modules
links more. The runtime's RAM is its arena and module, taken from the heap and bounded per
program by the worst-case memory analysis, so it is not a property of the image.

## Key performance indicators

A KPI here is a figure whose movement says the project is getting closer to, or further
from, its value proposition of definitive worst-case bounds on small and regulated
targets. Six are recommended as the headline set.

| KPI | Definition | Why it matters | State |
|---|---|---|---|
| Runtime flash | `vm-verify` flash above baseline | What an embedder pays to host verified bytecode | Tracked, ceiling enforced |
| Bound tightness | Measured worst-case cycles and memory over the analysed bounds, across the calibration corpus | A sound but loose bound is unusable, so this measures the bounds' usefulness | Partly measured by `keleusma-bench`, not tracked |
| Differential agreement | Divergences between the self-hosted and reference compilers, and between the native and virtual machine routes | The project's correctness oracle | Enforced at zero by the self-host tier |
| Proof coverage | Machine-checked theorems over the obligations stated, and admitted steps left open | The certification argument's progress | Not started, awaits the proofs line |
| Advisory exposure | Open security advisories and the days each has been open | Supply-chain risk for a security-relevant runtime | Visible in Dependabot, not tracked |
| Critical path | Minutes from a merge to its branch run's result, and the longest shard | How fast a correct change can land | Measured by hand, not tracked |

## Supporting metrics

Grouped by area. **Tracked** means a check or report produces it today. **Cheap** means one
script or job would. **Later** means it needs work first.

**Product.**
- Flash and static RAM per configuration. Tracked.
- The `Value` slot size, pinned at 32 bytes by a `const` assertion, and the opcode count,
  pinned by `tests/claimed_counts.rs`. Tracked, as invariants.
- Load and verification time per kilobyte of module, which bounds the cost of a hot swap.
  Cheap, with `keleusma-bench`.
- Interpreter throughput on the host and on the board. Cheap on the host, later on the board.
- The construct-support boundary of the self-hosted compiler, its Ok, Gap and RefRejects
  counts. Tracked by `tests/selfhost_codegen.rs`.

**Verification and quality.**
- Tests by tier, and retried tests per run, which `scripts/ci_flaky_report.py` reports.
  Tracked per run, not as a trend.
- Fuzz executions per night per target, and crashes found. Reported per run in the fuzz
  job. Cheap to collect.
- `unsafe` blocks in the runtime crate. Cheap.
- Line coverage of the test suite. Later, with `cargo llvm-cov` in a job.
- Lines of code by category, the test-to-code ratio and comment density, from
  `scripts/loc.sh`. Tracked on demand.
- Known non-conformances recorded against the standard. Cheap, by counting the register.

**Delivery.**
- Lead time from a pull request's opening to its merge, merges per day, and runs per merged
  pull request, as measured on 2026-11-05. Cheap, from the GitHub interface.
- Time a version branch spends red, and fixes needed within a day of a merge. Cheap.
- Release gate duration and days since the last release. Cheap.

**Security and supply chain.**
- Runtime dependencies in a `no_std` build, and their count over time. Cheap, from
  `cargo tree`.
- Releases signed over releases cut, once signing starts. Cheap.

**Documentation.**
- Broken links, held at zero by `tests/documentation_links.rs`. Tracked.
- Public items without documentation. Cheap, with `missing_docs` reported.
- Untranslated strings in the book's translation. Cheap, from the `.po` file.

**The agent process, particular to this project.**
- State-file sizes against their budgets, held by `tests/state_file_budget.rs`, and the
  largest handoff, which was 12,625 lines on 2026-11-05. Partly tracked.
- Tool error rate after a compaction, from `context_quality.py`. Measured on demand.
- Unacknowledged interline messages and their age. Cheap.
