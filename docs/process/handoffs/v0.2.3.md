## Findings you may want, since they are about the shared language rather than my slice

- **Your two reported constraints are confirmed against the reference**, not merely believed.
  Locals are immutable, rejected at **parse** ("assignment is only supported for data block
  fields"); a runtime-range `for` needs `limit`, rejected at **verify**.
- **`require word >= 32` does not protect a program using constants above `i32::MAX`.** With no
  `require` at all, a source carrying `0xFFFFFFFF` **compiles for a 32-bit target without
  complaint**. Nothing else catches it. If any native lowering bakes wide constants, the guard
  has to be explicit. `wire.kel` declares `>= 64`.
- **`Byte as Word` zero-extends** (`0xFF` reads as 255), and **`as Byte` truncates silently**
  (`300 as Byte` is 44, no fault), though the type checker does demand the cast on assignment
  into a `[Byte]`.
- **`lsr` is logical over the full word**: `(0 - 1) lsr 1` is `2^63 - 1`.
- **A bounded `for` works inside a `fn`, nested, and across a call boundary.**
- **`Word as Byte` truncates silently and the spec said the conversion did not exist.**
  `docs/spec/TYPE_SYSTEM.md` claimed "No other type conversions are available through the
  `as` keyword" while listing only `Word`/`Float`. Six exist. Corrected on a branch behind
  the running gate. If any native lowering forms a byte from a wider value, the narrowing is
  silent — no fault at compile time or run time.
- **`Vm::new_with_arena_capacity` does not exist**, though a rustdoc comment in `src/vm.rs`
  told hosts to call it, so it rendered into the published API docs. A host sizes the arena
  by constructing it and passing it to `Vm::new`. Also corrected.
- **A probe needs its own control.** Six constructs appeared rejected at `Vm::new` purely
  because my arena carried zero persistent capacity, which reads exactly like a language
  restriction. `required_persistent_capacity_for` plus `resize_persistent` is the fix.

## Method rules this arc paid for

- **A control executes a test's precondition** — that the predicate measures what you think it does.
  It runs in one direction only, so a **must-fire case** (defect present, check must report) and a
  **must-not-fire case** (defect absent, check must stay quiet) are both required. All three controls
  I ran on 2026-08-08 were must-fire cases and I recorded them as if they closed the question.
- **Executed beats reasoned, and an executed claim is only as good as its unexecuted preconditions.**
  A measured 3.7× speedup this arc came from a build with a live bug in it.
- **Rehearse a history rewrite on throwaway refs.** Two consecutive wrong rebase ranges of mine were
  caught that way.
