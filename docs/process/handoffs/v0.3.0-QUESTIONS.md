      the header carries the one figure of question 22. That changes the
      header contract and over-provisions every native region by the virtual
      machine's own terms.

    agreed in sequence 182.

13. **A host string ABI.** Answered 2026-10-28.
   > a and b. Keep plain Text literal-only in native code, and use the bounded Text<N> type for dynamic text. Also use the two-word pointer and capacity where capacity==length for literals.
   
   This line reads it as follows, and the reading is to be confirmed. A literal is carried natively as two words, a pointer to its bytes and a capacity, and for a literal the capacity equals the length. Dynamic text is `Text<N>`, which V0.2.X builds. The option letters refer to [`ORDER_6_DECISION_OPTIONS.md`](../../decisions/ORDER_6_DECISION_OPTIONS.md).

   Clarified by the operator on 2026-10-28.
   > The idea is that text has a capacity, and data that fills or partially fills the capacity. For a literal, we generally just want to fill the capacity. For dynamic text, we may have a capacity of 1000 character, but only use 231 of them. Therefore, one word records the capacity, and the other holds a pointer to the data. I could see using three words for dynamic text, and only two for text literals.

   This line's reconciliation with the authorized flat `Text<N>` storage, given
   in session and proceeded on unless the operator objects, is that the words
   are the passing representation, not the storage. A literal passes as a
   pointer and a capacity equal to its length. Dynamic text passes as a
   pointer, a capacity of `N` and a length, viewing a `Text<N>` that is still
   stored flat, so worst-case memory stays static.

   The operator added on 2026-10-28, on learning that V0.2.X was already
   building that form.
   > If the described form is already building, then we have a development nop.
