# V0.3.X open questions for the operator

> **Navigation** [Brief](./v0.3.0-BRIEF.md) | [Archive](./v0.3.0.md)

The operator asked on 2026-10-25 for this line's open questions to be
accumulated here, to be answered when convenient. Each entry says what this
line assumed meanwhile, so work does not wait on an answer. An answered
question is moved to the bottom with its answer and date, and its provenance
is the operator's own words in a session.

## Open

1. **Native WCET, hard or best effort.** Roadmap open decision 1. Order 4
   assumed best effort, in bytecode cost units, as the native codegen strategy
   recommends for V0.4.0. No native time bound is claimed. See
   [`ORDER_4_COMPLETION.md`](../../decisions/ORDER_4_COMPLETION.md).
2. **The flat-machine ISA in the bytecode.** Roadmap open decision 3 asks
   whether the B28 redesign lands in V0.3.x or V0.4.x. Its bytecode half, kind
   carried by the opcode, would change the instruction set and the wire format,
   which needs authorization. Order 5 took the native half only. See
   [`ORDER_5_PLAN.md`](../../decisions/ORDER_5_PLAN.md).
3. **The root `scripts/` pipe pattern.** Several root scripts test or truncate
   output through an early-exiting pipe under `pipefail`, which can turn a true
   condition false under SIGPIPE. Should this line report it to V0.2.X, which
   owns those scripts? Not yet reported.
4. **`opt-level = 1` for `native_codegen`.** The root profile has it and this
   detached package does not. Should it be applied here? Not applied.
5. **The lexer's missing cost claim.** The verifier's text pass refuses a
   comparison of two `Word` call results in `intern_id`, so the lexer exports
   no composed cost claim. Reported to V0.2.X, which recorded it as an operator
   question. Should this line wait for a verifier change, or carry a narrower
   claim of its own?
6. **More native corpus roots.** `src/hosted/interp.kel` and
   `src/crypto_frame/frame.kel` are outside the native corpus. Should they be
   added, which would make them lower natively and enter every census?
7. **`RUNTIME_FAULTS.md` native default values.** Superseded on this line by
   the 2026-10-20 ruling. V0.2.X recorded the question of revising the
   specification for the operator.

8. **Hot swap acceptance beyond the schema hash.** The native swap applies the
   virtual machine's rule, which compares slot names and visibility but not
   slot types, plus equal shared sizes. Should either shape compare types too?
   That would change `compute_schema_hash`, which V0.2.X owns.
9. **The rest of the corpus toward static kinds.** Twelve corpus coroutines
   still need a run-time kind, mostly for an operand that may hold `Unit` or a
   value after `Reset`. Removing that would need the language or the verifier
   to rule the ambiguity out. Is it worth pursuing before V0.4.0?
10. **Two unique Kaizen branches.** `feat/native-stream-refusals` holds two
    inventory records found nowhere on `v0.3.0`. This line asked Kaizen to keep
    it. Should the records be restored into `NATIVE_LOWERING_INVENTORY.md`, or
    may the branch go?

11. **`native.yml` paths and CI load.** Kaizen measured that a process-note
    commit on `v0.3.0` starts two macOS native jobs of about 41 minutes each,
    because `native.yml` watches `docs/decisions/**`, the reverse prompt and
    this line's handoff. Native tests do read some of those documents. Should
    this line audit exactly which, and narrow the paths?

12. **Executing the Linux targets.** Tier 1 includes x86-64 and AArch64
    Linux. Both build here and their objects are checked, but neither runs,
    because native continuous integration is macOS only and this machine has
    no Linux runtime. A Docker client is installed without a running daemon.
    Should a Linux native CI job be added, or a local container be used?
13. **A host string ABI.** Native code carries a `Text` literal as a
    `{ i64 len, bytes }` record and passes that address to natives. A `Text`
    from a call, a parameter, a native or a field cannot be compared and a
    `Text` field cannot be packed, because no ABI says what such a word is. What
    should the native representation of a `Text` crossing the host boundary be?
14. **Opaque handles natively.** Opaque host references have no flat layout and
    are refused on every native route. What should their native ABI be?
15. **Rosetta and an `x86_64` Rust target.** The `x86_64-apple-darwin` Rust
    standard library is not installed, so the Rust lexer host and its stack
    probe run on `arm64` only, while C hosts run on both. May this line install
    that target with `rustup`?
16. **One command for both shapes.** `kel-native` lives in the detached
    `native_codegen` package so LLVM stays out of the main build. Should the
    `keleusma` command line offer native output through it?
17. **Releasing V0.4.0.** Order 6 defines the V0.4.0 milestone. Publication
    is held, and nothing is tagged or published by this line.
18. **What this line's Order 6 still needs from V0.2.X.** Added 2026-10-27.
    V0.2.X's [Order 6 audit](../../decisions/ORDER6_COMPLETION_AUDIT.md),
    absorbed in absorption 111, records its Order 6 as not complete. Every
    gate condition is met except five forms, the information-flow labels and
    the newtype, which wait on V0.2.X's own operator question 10. This line's
    [Order 6 record](../../decisions/ORDER_6_COMPLETION.md) lists V0.2.X's
    Order 6 as one of its unmet dependencies. The native compiler consumes the
    reference compiler's bytecode, and the self-hosted output is required to
    be byte-identical to it, so the self-hosted compiler's completeness does
    not by itself change what native code is given. Is the dependency then
    met by the reference corpus, or does the operator intend it to wait on
    V0.2.X's Order 6 as recorded? This line assumes meanwhile that it waits,
    and changes nothing. One of the five forms appears in
    `examples/scripts/07_refinement.kel`, which the native corpus fingerprint
    lists. Whether native lowering reaches that file was not checked for this
    entry.
