13. **A host string ABI.** Answered 2026-10-28.
   > a and b. Keep plain Text literal-only in native code, and use the bounded Text<N> type for dynamic text. Also use the two-word pointer and capacity where capacity==length for literals.
   
   This line reads it as follows, and the reading is to be confirmed. A literal is carried natively as two words, a pointer to its bytes and a capacity, and for a literal the capacity equals the length. Dynamic text is `Text<N>`, which V0.2.X builds. The option letters refer to [`ORDER_6_DECISION_OPTIONS.md`](../../decisions/ORDER_6_DECISION_OPTIONS.md).

   Clarified by the operator on 2026-10-28.
   > The idea is that text has a capacity, and data that fills or partially fills the capacity. For a literal, we generally just want to fill the capacity. For dynamic text, we may have a capacity of 1000 character, but only use 231 of them. Therefore, one word records the capacity, and the other holds a pointer to the data. I could see using three words for dynamic text, and only two for text literals.

   This line's reconciliation with the authorized flat `Text<N>` storage, given
   in session and proceeded on unless the operator objects, is that the words
   are the passing representation, not the storage. A literal passes as a
   pointer and a capacity equal to its length. Dynamic text passes as a
   pointer, a capacity of `N` and a length, viewing a `Text<N>` that is still
   stored flat, so worst-case memory stays static.

   The operator added on 2026-10-28, on learning that V0.2.X was already
   building that form.
   > If the described form is already building, then we have a development nop.

20. **The definite-initialization rule is held.** Raised 2026-10-28, answered 2026-10-30.
   > Proceed with option a.

   Given first-hand in session, after the options below were restated. It was relayed to V0.2.X, which owns the rule, in interline sequence 154, together with this line's reading, marked as its own, that the rule refuses a read only where it proves the slot unwritten on every path and admits both idioms reported.

    V0.2.X reported in interline sequence 131 that its rule, built on
    `feat/v02-definite-init` at `0d1ec837`, rejects programs the suite
    treats as valid, in two classes. A composite private slot written only
    on the first pass, then read, is rejected, and composite private fields
    admit no initializer, so that idiom has no accepted form. For locals,
    the handled indexed write writes a scratch local and reads it under the
    same comparison, which a path-insensitive analysis rejects. V0.2.X owns
    the rule and holds it pending your decision. This is its report, relayed.

    This line's measurement bears on the choice. Starting unwritten slots
    empty instead of `Unit` removes 1 of 5995 instructions needing a run-time
    kind, and makes one coroutine static. The ten piano roll coroutines stay
    dynamic for another reason, a discarded native result of unknown kind,
    which this line will measure on its own side. The rule is therefore not
    what tag removal mostly waits on.

    Measured on 2026-10-29, the piano roll figure was this line's census
    counting values no instruction reads, and the census now counts only
    reads. Two coroutines and 21 instructions need a run-time kind. The
    private rule frees `14_frame_log.kel`, one of the two, and removes one
    instruction. The other twenty are in `interp.kel`, which no start rule
    changes. The recommendation stands because the rejected idioms are in
    use, though the rule's share of what remains is now larger.

    Measured on 2026-10-30, V0.2.X's change to checked arithmetic made
    `interp.kel` static. One coroutine, `14_frame_log.kel`, and one
    instruction now need a run-time kind, and that one is the case the
    private rule frees. The rule is therefore now what the last tag waits
    on. The recommendation still stands, because freeing one coroutine is a
    small gain against rejecting idioms in use.

    - **a. Narrow the rule to what it can prove now, and keep the tags where
      it cannot.** Recommended by this line, because the measured gain is
      small and the rejected idioms are in use.
    - b. Change the compiler to write every slot on every path.
    - c. Admit initializers for composite private fields, so no private slot
      starts as `Unit`.
    - d. Defer the rule, and remove tags here only where the analysis already
      proves a single kind.

    Meanwhile this line plans no tag removal on the rule, as V0.2.X asked.
