## THE HEADLINE WAS INFLATED, AND SEEDING IS WHAT INFLATED IT

**`is_vacuous` asked whether the shared segment was all zero.** A seeded module holds a non-zero
segment *before it executes a single operation*, so that test answered "was this module seeded"
rather than "did it do anything". **Being seeded was sufficient to leave `KNOWN_VACUOUS`.**

Three `verify_*` stages left the list on that basis on 2026-08-15 and 2026-08-16, taking the headline
from 40 to 44. The test now compares the final segment against **the bytes the module was handed**,
and all three are vacuous again. The count is 42.

**`reconstruct.kel` stayed out**, because it writes the reconstructed forest back. That is the
difference between a stage that does observable work and a stage that merely received an input, and
before the repair the harness could not tell them apart.

**Then the three left again, and this time it is earned.** Each verify stage writes its verdict as
1 for reject and 0 for accept, and the seeded buffer already holds 0 — so a WELL-FORMED subject made
them decide and change nothing. They are now seeded with a chunk carrying **the defect each one
actually checks for**, the verdict moves to 1, and the segment moves with it. The count is 45.

**42 → 45 is not evidence that 44 → 42 was wrong.** The drop removed a departure caused by seeding
alone; the rise is a departure caused by a moved observable. Different mechanisms, and only the
second one means anything.

**Each stage needs ITS OWN defect.** One mutation for all three was tried first, and
`verify_structural` accepted the operand-stack underflow — correctly, since it latches block-nesting
malformation, not depth. Reusing one mutation would have read as "that stage cannot be made to
reject", which is false. It rejects an unclosed block opener.

**The ACCEPT direction is asserted separately**, in `probe_stage_vacuity`. A rejecting seed alone
would be satisfied by a stage that rejects everything. **Do not restore a well-formed subject to the
differential to make the stages look better behaved** — on a well-formed chunk they are vacuous
again, and correctly so.

**Do not recover a count by shortening the list.** It is asserted by set equality in both
directions precisely so that editing it is not the easy path.

## Process rules that keep paying

- **AN EXPERIMENT THAT CANNOT FAIL IS NOT EVIDENCE, AND IT LOOKS EXACTLY LIKE SUCCESS.** The first
  `Trap` observable passed while none of its three subjects emitted `Op::Trap` — they fault through
  the division guard and the bounds check. Only mutating the opcode said so. The repair is not a
  better subject list but an assertion that each subject CONTAINS the construct it is named for.
  Same family as the `PushImmediate` vacuous mutation and the nine stages agreeing on doing nothing.
- **A FIXED BUDGET BESIDE A CHANGING HARNESS IS A FALSE-POSITIVE GENERATOR.** `mutation_sweep.py`
  counted a timeout as detection against a flat 20s budget; widening the differential to 24 seeds
  took `wire.kel` to 30.7s unmutated, and the sweep reported EVERY opcode detected — four false
  closures. `PushImmediate` caught it, because its mutation edits an arm with zero sites and
  therefore cannot be detected. Budgets are now measured by `calibrate()`. **Keep a case whose
  answer is fixed in advance in every sweep.**
- **A SILENTLY-UNBUILT INPUT AND A SILENTLY-REJECTED ONE PRODUCE THE SAME NUMBER.** Seeding
  `verify_depth` first reported it unmoved — the predicted finding — and the cause was a subject
  source that did not parse, so no seed existed. The harness prints `APPLIED …` / `NOT BUILT — why`
  for exactly this reason. **Without that line, "seeded and unmoved" is worthless.**
- **SUSPECT YOUR OWN HARNESS FIRST.** The multihead 3-against-2 was reported twice as a verifier
  defect before anyone checked. Two of three candidates were eliminated by measurement — including
  this harness's own positional pairing, which `q1`'s header warns produces a violation
  indistinguishable from a real one.
- **A COUNT MOVING IN THE EXPECTED DIRECTION IS NOT EVIDENCE THE EXPECTED THING MOVED.** Check WHICH
  module left the list.
- **`lower_module` returning `Ok` is not verification.** A fact about the compiler, not the program.
  It stood in for verification twice and was wrong both times.
- **Probe before implementing, AND before escalating.** Twice a blocker was raised as an operator
  decision when measurement showed it was not.
- **Run the VM side FIRST** in any corpus-wide harness: a trapping module reports an error there and
  kills the process with SIGTRAP natively.
- **Guard vacuity**: an empty call log and two all-zero data segments compare equal.
- **A pull request based on a FEATURE BRANCH is never gated at all.** `ci.yml` triggers
  `pull_request` only on `main` and `v*`, so a stacked pull request produces **zero** runs and looks
  merge-ready. PR #102 sat that way for its whole life. Two pull requests on disjoint files gate
  fine in parallel.
- **`ci.yml` HAS a `concurrency` group since 2026-08-16**, and it is scoped: superseded
  pull-request runs cancel, branch verification runs do not. **The obvious `github.ref` form would
  have cancelled the branch runs**, which this line consults after every merge to distinguish an
  integrated state from a proposed one. Asked for three times, corrected by them on landing.
- **`git status` PRINTS THE STAGING COLUMN; READ IT.** ` M` with a leading space is UNSTAGED. PR
  #111's message claims ignore rules it does not contain, and it is merged, so that claim is
  permanent.
- **Write the prune manifest BEFORE deleting a branch**, never after.
- **DELETING A REMOTE BRANCH NEEDS `--no-verify`.** The pre-push hook runs the full nextest suite —
  2012 tests, ~466s — and the push then dies with exit 141 while the pipeline reports success. Three

  gate protects.
- **VERIFY THE REF AFTER A PUSH, NOT THE GATE OUTPUT.** `git ls-remote --heads origin <branch>`.
  This has now caught a failure in both the push and the delete direction.
- **DO NOT PIPE A LONG PUSH THROUGH `head`/`tail`.** It truncates the line that would explain a

### The two ABI decisions this arc made, both host-visible

- **`kel_native_<mangled>`, called directly.** Name-derived rather than index-derived because
  `Vm::run` binds natives BY NAME through `native_name(idx)`; an index would tie the object
  file to declaration order. Each separator character becomes one underscore, so `host::two`
  and `host_two` stay distinct — collapsing `::` reads better and collides the likelier pair.
  Not injective even so, so a **module-level** precondition refuses a collision, because no
  call site can see a hazard that is a property of a pair.
- **`{ i64 len, [n+1 x i8] bytes }` for a static string, address in the slot.** The length is
  explicit because a Keleusma string is a byte string: a raw NUL inside a source literal is
  accepted by the lexer, VERIFIED not assumed, so a bare `char*` would truncate one. The
  trailing NUL is added anyway for an ordinary C host.

  **OPERATOR DECISION OWED.** On the virtual machine a string-taking native receives a
  marshalled `String`; natively it receives this pointer. The two embeddings are therefore
  **not source-compatible** for a string-taking native. Inherent to ahead-of-time lowering
  rather than a defect, but it is new host surface and the operator may want a different
  shape.

### Method rules this arc paid for, newest first

- **Op presence and a refusal list are biased in OPPOSITE directions, and do not cancel.** A
  ranking over-states what removing one class frees; `module_refusals` under-states what
  remains, because it stops at the first blocker per chunk. The instrument that hides nothing
  is a full op histogram over every chunk. It found the real blocker ordering to be the
  opposite of the attention ordering: static strings had been the named item for two
  increments at **10 instances**, while native calls were never ranked at **999**.
- **A discredited number can still come true — check WHICH word was wrong.** `static-str = 11`
  was measured at 1 and correctly discredited. It then freed exactly 11 once native calls
  landed. It was never wrong about eleven; it was wrong about *alone*.
- **Ask what the CONSUMER needs before designing the fail-closed rule.** Zero of 999 native
  sites carry a return shape, so refusing an unknown return would have lowered none of the
  family — discovered before implementing, by measuring `native_return_shapes` directly.
- **A subject that "REFUSES" may be REJECTED BY THE REFERENCE COMPILER instead.** When the
  boundary test's subject entered the subset, every `probe_unsupported` case reported LOWERS;
  three of five new candidates turned out to be reference rejections, which are not subset

## Findings from this increment that touch the shared language

- **`Op::Add`, `Op::Sub`, `Op::Mul` and `Op::Neg` carry no `Int` operands.** Consolidation B
  narrowed all four away; the compiler emits `Checked*; PopN(2)` for every `Word` expression and the
  VM raises a type error if an `Int` reaches `Op::Add`. The opcode names actively mislead. I had
  planned an increment around them and it would have produced four lowerings that no compiler
  output ever reaches.
- **`CheckedMul`'s `u8` operand is the Q-format fraction-bit count**, zero being integer multiply.
  The inventory had it recorded as unprobed.
- **`GRAMMAR.md` line 747 says the runtime pushes `(high, low, flag)`.** It pushes `(low, high,
  flag)`. The arm *bindings* are correct — `overflow(h, l)` does bind high then low, because the
  compiler reads the right slots — so only the parenthetical is wrong. This is the same defect
  class as the `Op::CheckedAdd` doc comment you already fixed, in a different document, and it is
  on your surface rather than mine.

  order left the range-`for` counter reading the high word, so the induction variable never
  advanced and the suite hung rather than failed. If you ever mutation-test, use a hard timeout —
  and on macOS that is `gtimeout`, since **`timeout` does not exist**. Same shape as the `tac`

## Standing facts worth not rediscovering

- **MacPorts LLVM needs `-L native=/opt/local/lib`.** Its absence fails at `ld`, not at the binding,
  which is the wrong layer to start debugging at. Carried in `native_codegen/.cargo/config.toml`,
  scoped to the package so it never reaches your builds.
- **The verifier admits far less than the parser.** A data-dependent `break` compiles and then fails
  with "no statically extractable iteration bound". The admitted loop forms are the range `for` and
  an unconditional break.
- **Locals are immutable** — "assignment is only supported for data block fields". Accumulating
  across iterations needs a data block. This is why a loop's iteration count is not observable with
  the current subset.
- **A range `for` emits no coroutine or composite opcode.** I previously claimed the opposite, from
  counting `Op::` across all of `compile_for` including its composite paths. It was wrong.
- **`.stack_sizes` is reachable but constrained.** LLVM emits per-function frame sizes, which is what
  a native worst-case-memory bound needs. It is absent from the `llvm-c` headers and from both Rust
  bindings, so it needs an out-of-process `llc --stack-size-section`, and it is **ELF-only**: absent
  on Mach-O, present on `thumbv7em-none-eabihf`. It falls the right way, since the embedded targets
  are where a stack overflow is unrecoverable.
