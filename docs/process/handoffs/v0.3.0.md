## What you inherit that is worth knowing

- **`BYTECODE_VERSION` is 2.** The auxiliary body is the wire format v2 container, not an rkyv
  archive. `docs/spec/WIRE_FORMAT.md` specifies it and is now accurate.
- **`tests/perf_canary.rs` is a tripwire, not a benchmark.** It fails if the VM's constant-load path
  slows past a deliberately slack ceiling. If it fires, **profile before touching the ceiling**: the
  class it catches is a hot-path read that has become proportional to the whole module, and every
  correctness test will keep passing. It exists because a merge-ready branch was once forty times
  slower with a fully green suite.
- **`scripts/release-gate.sh` reaps orphaned test binaries as a preflight.** An interrupted gate
  leaves its test binary reparented to PID 1 at full CPU; one was found burning four cores for ten
  hours and halving the machine.
- **Tiered verification** is in `PROCESS_STRATEGY.md`. Full gate before every **merge**, not after
  every change; batch three or four increments per gate. A full gate is roughly 1h40m.

## Rules of parallel operation

From [`PARALLEL_DEVELOPMENT.md`](../PARALLEL_DEVELOPMENT.md) section 3 and 4:

- **Do not overwrite `REVERSE_PROMPT.md`.** It is single-writer and the `v0.2.3` session holds it.
  Write here instead.
- **`DESIGN_JOURNAL.md` is append-only.** Append a dated, branch-tagged entry at the top.
  Append/append conflicts resolve by keeping both.
- **`TASKLOG.md`**: claim one row, tagged with your branch, and edit only your own.
- **Do not run a full gate while the other session is running one.** `release-gate.sh` is CPU-heavy
  and the self-host tests already contend for cores; two at once inflates both agents' wall-clock
  substantially. `scripts/fast-check.sh` is cheap and safe to run concurrently.

## The contention risk worth naming now

The `v0.2.3` stream's next work is **step 6 of the wire-format programme, self-hosting the wire
format in Keleusma**, which will touch `src/selfhost/kel/`. If native codegen also touches those
stage sources, the two streams will contend on the same files.

The `.kel` stages are lockstep, which is why `AUTONOMOUS_IMPLEMENTATION_LOOP.md` runs the self-host
frontier as a single stream rather than parallelising it. This is not a blocker, but it is the one
place these two workstreams are likely to collide, and it is much cheaper to divide deliberately now
than to reconcile later. Worth agreeing the boundary with the operator early.

## Merging

Merge back with [`scripts/merge-to-trunk.sh`](../../../scripts/merge-to-trunk.sh), which rebases,
gates, re-checks that the trunk has not moved, then fast-forwards and pushes. It is a dry run by
default; pass `--execute`. Note its trunk is `v0.2.3` — confirm with the operator whether `v0.3.0`
merges to `v0.2.3`, or to `main` independently, before relying on it.
