# V0.3.X RESUME BRIEF — bounded on purpose

**This is the entry point for the V0.3.X native-code-generation line.** The full channel,
`v0.3.0.md` beside this file, is over ten thousand lines and is an **archive**: history kept
deliberately, newest material near its `► RESUME HERE` section. Read that when you need the why.
Read this to start.

**Deliberately, this file carries almost no figures.** Every count lives in the archive's state
table, which is **guarded** — `native_codegen/tests/handoff_figures.rs` re-derives each derivable
one from the tree and fails when they disagree. Copying them here would create a second place to
drift, which is the single most common defect this line has recorded about itself.

## 2. The gate — this line's whole verification story

```sh
cd native_codegen
tools/backend-gate.sh            # default features
tools/backend-gate.sh --narrow   # narrow-float-32
```

- **One invocation covers ONE configuration.** A single run is not both.
- **Roughly 10–20 minutes each**, longer from a cold build.
- **Run ONE per background command.** A chained pair has been killed mid-flight.
- **The tree must not move while it runs** — documentation included. The gate freeze-checks itself
  and reports `MOVED(N)` in the record; a phase that ran on a moving tree is not a measurement.
- **Continuous integration never builds this package.** Measured: zero occurrences of
  `native_codegen` in `ci.yml`. A root `cargo test` cannot reach a detached workspace root either.
  If you did not run the gate, nothing ran it.

`tools/gate-status.sh` answers whether the recorded verdict still speaks to `HEAD`, by diffing
every path the suite READS — not just the package. A nonzero answer is information, not an alarm.

## 3. Standing constraints

- **Root `src/` and root `tests/` are READ-ONLY here.** Report, do not repair. Check with commits
  **not reachable from `origin/v0.2.3`**.
- **No new opcodes.** The rad-hard minimal-ISA constraint is a design commitment, not a preference.
- **No `BYTECODE_VERSION` change without operator authorisation.**
- **Publication is held.**
- **The byte-identical differential against the reference VM is the correctness signal.**
- **Absorb before trusting any corpus-derived figure**, and run the conflict check in its own
  command before predicting anything about the merge.

## 4. The open item

**Lower a `yield` nested inside an `if`** — `lexer.kel`'s shape. Scoped, not started, in
`docs/decisions/WORKSTREAM_B_FIRST_INCREMENT.md`, which carries the measured facts that bound it and
the wrong turns.

⚠ **The one that inverts the obvious inference: the tail-shape result does NOT transfer.** A tail
yield was measured to be **no suspension at all** — the module declares no host yield hook, contains
only `kel_chunk_0` and `llvm.trap`, and the entry RETURNS a pointer where the reference SUSPENDS. A
yield in an `if` is the first case needing a real suspension, and no existing evidence covers it.
Reading "tail yields already lower" as a running start would be wrong.

## 5. How this line establishes things — the part worth adopting

The guards are not bureaucracy; each exists because something specific went wrong, and each has
caught its own author since. Run them and believe them over your own reading.

| guard | what it refuses to let you do |
|---|---|
| `handoff_figures` | let a state-table figure drift from the tree, or the banner disagree with the table |
| `prediction_stamp` | file an absorption prediction without the tree it was computed against |
| `reach_census` | let the suite read a path the staleness reporter does not watch |
| `kind_arm_census` | let the accounted residue move unnoticed |
| `gate_record` | let the record be malformed, or name a commit that does not exist |
| `corpus()` / `corpus_sources()` floors | let a silent empty corpus read as agreement across every census |

**Three failure modes recur, and all three are documented with their instances.**

1. **A figure asserted without measuring it.** A job count of "fourteen" came from a `head -14`
   listing; an activity ranking was published from no measurement at all.
2. **An instrument's output read as a statement about the subject.** A truncated listing asserted on
   as complete; `grep -c` counting lines rather than occurrences; a probe's seeder capability read as
   project coverage. **For "what does this harness cover", the instrument is its own test list and
   its own reported counts — not a grep.**
3. **"What remains" written without reading what is done.** A whole roadmap assessment was retracted
   for this. The archive's `► WHAT IS DONE, SO IT IS NOT REDONE` section exists to prevent it.

**The method that caught nearly everything**: ask two instruments the same question and compare. Not
review, not re-reading your own output. Two of this line's better findings came from a phase verdict
disagreeing with a record, and a refusal sweep disagreeing with a census.
