# Sites in Called Functions, an Excluded Case of Increment B2

> **Navigation**: [Increment B2](../region_core/README.md) | [The prose proof](../../COMPOSITE_REGION_REUSE_PROOF.md)

Increment B2's checker forbids allocation inside functions, which excludes the case of a site
executed twice in one scope through two calls. This directory lifts that restriction, in the Rocq
Prover, version 9.3.0. **For every module the call-site checker accepts and every plan giving
distinct sites distinct slots, the run that reuses the plan's slots and the baseline run either
both stop or both finish with the same observations, for every host, every fuel and every number
of stream cycles, although functions may allocate.** The checker accepts every module B2's checker
accepts, so nothing B2 covers is lost. Every named result is checked with no axiom.

## The checker

`ShapeC.region_checkC` is B2's checker with two changes. A function body is checked with
allocation allowed, and its result must still be all scalars, so no handle escapes it. Each entry
of the function table records the function's result shape and the sites it may allocate, directly
or through its own calls, computed in function order by `sites_b`. And a call is refused while
the caller holds a live handle of any site the callee may allocate, because the callee's
allocation would then write the slot that handle names. Every other rule is B2's.

## How it is proved

`Frame.frame` proves, for every plan, that a run of a block writes memory only at cells of the
block's allocation sites, at allocation indices no smaller than the length of the allocation
record when the run began, and that the record only grows and the epoch does not change.
`SimC.simulationC` is B2's simulation with a new call case. There the two runs of the callee are
related by the simulation itself, and the frame lemma, applied to both runs, shows that neither
writes a cell named by a caller's live handle. That handle is of a site the callee does not
allocate, which the call rule ensures, and of an index below every index the callee allocates,
so under an injective plan its cell differs from every cell the callee writes. Every other case
is B2's proof text, adapted by substitution. `CallSites.reuse_sound_calls` is the headline.
`Contains.calls_contains_b2` proves that every module B2's checker accepts this checker accepts,
with B2's table lifted to entries of no sites. On such a table the call rule is vacuous, and B2's
functions, checked with allocation forbidden, allocate nothing.

## How to check it

```sh
eval $(opam env --switch=rocq)
docs/proofs/rocq/call_sites/check.sh
```

The script follows the hardened scripts of the other directories. It builds B2's sources as its
dependency, then this directory's eight modules. It fails unless no source of this directory,
dependencies not scanned, holds an admitted or assumed proof, a warning silencer or a `Redirect`, scanned with comments removed and whitespace
collapsed, the pin and control files open no section and declare no hypothesis, variable or
context, every module compiles with no output, `rocqchk` reports no axiom and no unsafe
construct, all 44 named results are closed, and `Statements.v` holds its 18 pins, counted with
comments removed, each naming a distinct item of `Claims.v`, with every item pinned. `Claims.v` states the headline, the frame lemma, the containment of B2, six controls, four
equations fixing the control modules, and five definition equations, and `Statements.v`, generated by `tools/rocq-pins/genpins.py`, imports no
module of the project and pins each of those items by the type Rocq printed with fully qualified
names. On 2026-11-21, in a copy under `tmp/`, removing the call rule from the checker made
`SimC.v` fail to compile. That is a mismatch of the proof script, not by itself evidence that the
theorem needs the rule. The stronger evidence came from the audit of the same date, which found
by execution that without the rule the checker accepts `live_across_call`, whose runs diverge,
and a nested variant whose main holds a site-1 handle across a call to a function that calls
`alloc_fn`. With the rule both are rejected. No log is kept in the tree. Continuous
integration does not yet run the script.

## The controls

- `twice` calls a function that allocates at site 1, twice in each cycle. B2's checker rejects
  it, since its functions may not allocate. This checker accepts it, its reuse run under `P1`,
  which puts site 1 in slot 0, agrees with the baseline, and `twice_sound` applies the headline.
- `live_across_call` allocates at site 1, then calls the same function while that handle is
  live, then reads the handle. This checker rejects it by the call rule, and its reuse run really
  diverges, the read seeing the callee's value, so the call rule guards a real hazard.

## The trusted base

The Rocq kernel, `rocqchk`, the standard-library modules `List`, `Arith`, `Bool` and `Lia`, B2's
definitions, and the statements and pinned definitions as written. The pins fix the definitions
of `live_in`, the call rule, `framed`, `P1`, the controls' `log_of`, and the control modules
`alloc_fn`, `twice` and `live_across_call`. They do not fix the rest
of `shapeC_b`, `sites_b`, `check_funcsC` or B2's definitions.

## What is not covered

- **Arm groups and shared slots.** The headline needs an injective plan. Combining this checker
  with the join checker of [`../shared_slots/`](../shared_slots/README.md) was not done.
- **Every other limit of B2**, among them refined confinement, the escape-copy discipline,
  termination of this checker's modules, memory accounting, and any relation to the shipping
  virtual machine or verifier.
