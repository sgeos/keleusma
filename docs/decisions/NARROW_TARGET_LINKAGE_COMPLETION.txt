COMPLETION CONDITION — narrow-target linkage census (V0.3.X, native_codegen)

Ordering is NOT a completion criterion. The properties below may be reached in
any order, by any route. Judge the end state of the tree and the transcript, not
the sequence, the branch, or the process used to get there.

DONE when all of the following hold.

1. A BARE-METAL TARGET IS MEASURED, OR ITS UNAVAILABILITY IS THE REPORTED RESULT.
   Objects are emitted for a target with no operating system and no 64-bit
   hardware divide, and their undefined symbols are read. If the linked LLVM
   cannot produce that target, the record says so explicitly and states that the
   census could not be taken, rather than reporting a host measurement under a
   narrow-sounding name.

2. THE TWO TARGETS ARE COMPARED, NOT MERELY BOTH LISTED.
   The record states which symbols the narrow target requires that the host does
   not, and which it shares. A pair of unrelated lists does not satisfy this.

3. THE SYMBOLS ARE NAMED AND PARTITIONED.
   Every undefined symbol is placed in host contract, toolchain, or
   unclassified. An unclassified symbol is reported as unclassified. No symbol is
   moved between categories merely to empty one, and any reclassification shows
   the prior state.

4. THE PREDICTION IS RESOLVED AGAINST ITS OWN FALSIFIERS.
   A prediction with named falsifiers was recorded before measuring. The record
   states, for each falsifier, whether it fired. If the prediction failed, the
   record says so plainly and is not restated to match the measurement.

5. NON-VACUITY IS ESTABLISHED FOR THE NEW FORMAT.
   The tree contains an assertion that fails if no narrow-target object was
   emitted or if the symbol reader returned nothing from one. An absence claim
   about a format the reader may not support is not accepted on its own.

6. SYMBOL NAMES ARE NOT CORRUPTED BY FORMAT DIFFERENCES.
   The record or the code shows that leading-underscore decoration is handled
   per object format, so a name reported for one target is the name a linker
   would resolve on that target.

7. THE CONSEQUENCE FOR THE EMBEDDED EXAMPLE IS STATED.
   The record says what the measured symbol set means for a bare-metal host that
   links neither a compiler runtime nor a C library: which operations are safe,
   and which require a runtime the example does not currently name.

8. THE CONSEQUENCE FOR THE FLOAT LADDER IS STATED.
   The record says whether double-precision arithmetic lowers to runtime calls
   on the narrow target, and therefore whether narrower float rungs buy native
   instructions rather than only narrower storage. If this was not measured, it
   says that instead of implying it.

9. THE NEW TESTS SURVIVE ORDINARY PARALLELISM.
   Any test added is observed passing under the harness's default threading, not
   only under a single thread or in isolation.

10. NOTHING IS CLAIMED THAT WAS NOT RUN.
    Every symbol name, count, and pass/fail claim corresponds to a command whose
    output appears in the transcript. Carried figures are marked as carried.

11. THE PACKAGE IS GREEN, OR THE RED IS OWNED AND EXPLAINED.
    The native_codegen suite passes, or each failure is named with its cause and
    with a statement of whether the cause belongs to this package.

NOT completion criteria: which branch anything sits on, whether work is
committed, how many commits were made, the order of the eleven properties above,
or whether any other goal in the same session advanced.
