COMPLETION CONDITION — naming the mechanism behind wire.kel's empty-stack refusal

Ordering is NOT a completion criterion. Nothing below requires any particular
sequence, branch, commit shape, or process step. Judge only the end state of the
tree.

All of the following hold:

1. THE MECHANISM IS NAMED AND DEMONSTRATED, OR RECORDED AS UNKNOWN.
   Either the tree identifies what causes the empty-stack pop, with a test that
   fails if that explanation is wrong, or it states plainly that the mechanism is
   still unknown and lists what has been eliminated. A partial explanation is
   acceptable; an explanation asserted without a demonstration is not.

2. NO CAUSE IS CLAIMED FROM A COINCIDENCE ALONE.
   Any claim that some quantity or threshold causes the failure is accompanied by
   an input that isolates it: a program that crosses that threshold and differs in
   nothing else relevant. A claim resting only on two numbers matching is not
   sufficient, and the tree does not contain one.

3. THE REPORTED CHUNK NAME IS RESOLVED AS LABEL OR LOCATION.
   The tree states whether the name in the failure identifies the function whose
   records actually fail, and on what evidence. It does not treat the name as a
   location without that evidence.

4. ELIMINATIONS ARE RECORDED WITH THEIR MEASUREMENTS.
   Hypotheses ruled out are written down with the measurement that ruled them out,
   so they are not re-derived. An elimination without its measurement does not
   count.

5. THE wire.kel STATUS IS STATED TRUTHFULLY.
   Whatever wire.kel does is what the tree says it does. If it self-compiles
   byte-identically, it is in the byte-identity corpus and no pin claims otherwise.
   If it still fails, a test pins the current cause in the failing direction so a
   later change that moves the cause breaks the pin rather than passing silently.

6. NO CAPACITY WAS RAISED WITHOUT EVIDENCE IT WAS TOO SMALL.
   If any bound changed, the tree states the measurement that justified it. An
   unexplained bound increase does not satisfy this condition.

7. EVERY NEW OR CHANGED GUARD HAS BEEN MADE TO FIRE.
   Each has an input that provokes it and an assertion on what it reports. Where a
   guard is unreachable by construction, the tree says so and pins the invariant
   that makes it unreachable.

8. NO NEW OPCODE, AND NO BYTECODE_VERSION CHANGE.

9. THE SUITE IS GREEN ACROSS THE FEATURE SETS CONTINUOUS INTEGRATION BUILDS.
   Not one feature set. Every test file compiles under every feature set that
   builds it. The verdict comes from the test runner's own exit status, not from a
   filtered pipeline and not from a reported process exit code, and is corroborated
   by a second independent signal such as a count of completed test binaries.

10. DANGLING CITATIONS DID NOT GROW.
    No comment names a test, function, or symbol that does not exist, and the
    existing unresolved-citation register did not grow.

11. THE CHANNELS DESCRIBE THIS STATE.
    The resume channels and the handoff describe what the tree now does, separate
    what was measured from what was inferred, and carry any claim retracted during
    the work rather than deleting it.
