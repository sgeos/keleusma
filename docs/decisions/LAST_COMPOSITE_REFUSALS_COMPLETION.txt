COMPLETION CONDITION — the cause of the last composite refusals

Ordering is NOT a completion criterion. These properties may be reached in any
order, in any number of commits, on any branch. Judge the end state of the tree,
never the sequence that produced it.

TREE-CHECKABLE END STATE

1. The tree records, for each module the backend refuses on composite
   construction, which specific refusal condition produced it, named rather than
   summarised. The modules are named, not just counted.

2. Any module cited as refusing on composite construction is shown to do so
   before a cause is read from it. A probe that does not reach the refusal
   settles nothing.

3. The recorded prediction that the composite class splits into a part needing
   operand-width recovery and a part not needing it is reported against: either
   confirmed by the observed cause, contradicted by it, or shown not to apply.
   The prediction is not used as evidence for itself.

4. Where the corpus was measured to decide between candidate causes, the
   measurement is stated, including one that ruled a candidate out.

5. No claim is made that the backend is nearly complete on the strength of a
   high percentage. The remaining refusals are described as the residue they
   are, and any expectation that they need different work from each other is
   stated rather than assumed away.

6. Nothing in the backend's lowering behaviour changed, and no operand-width
   recovery was implemented as part of this increment.

7. No file under src/, and none of src/selfhost/, src/confine.rs, src/verify.rs,
   src/bytecode.rs, src/vm.rs, src/wire_schema.rs, or .github/workflows/,
   differs from the v0.2.3 commit the branch has absorbed.

8. Both suites are green, each verified by BOTH cargo's own exit status AND the
   summed per-binary counts, with the two agreeing:
     - the main workspace, run so a failure does not truncate the run
     - native_codegen, which continuous integration does not build and whose
       local run is therefore its only gate
   The two are not run concurrently with each other, because the workspace
   carries a wall-clock guard that concurrent load makes fail.

9. Every census and gate figure quoted as current was re-derived against the
   present tree after the last change capable of moving it.

10. The handoff validates against the tree: its ancestry checks pass, and its
    stated suite and census figures match a fresh run.

11. No count is presented as evidence without the command producing it being
    recoverable from the surrounding text.

NOT REQUIRED

- Lowering anything, or making any refused module lower.
- Explaining the refusals that are not composite ones, provided the scope of
  what was examined is stated.
- Resolving the Fixed shared-slot ABI or the float entry ABI; both are held by
  the operator.
- Any particular branch name, pull request, merge, or commit count.

DISQUALIFYING

- Naming a cause that was inferred rather than observed.
- Reading a cause from a module not shown to refuse on the opcode in question.
- Presenting a prediction as confirmed without evidence independent of it.
- Describing the remaining refusals as trivial or nearly closed.
- A guard that cannot fail, or whose ability to fail was never shown.
- A suite result read from a pipeline's exit status rather than the command's.
