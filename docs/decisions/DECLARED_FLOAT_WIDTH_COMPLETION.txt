COMPLETION CONDITION — the hard-coded declared float width (V0.3.X)

Ordering is NOT a completion criterion. The properties below may be reached in
any order, by any route. Judge the end state of the tree and the transcript, not
the sequence, the branch, or the process used to get there.

DONE when all of the following hold.

1. REACHABILITY IS ESTABLISHED BY MEASUREMENT.
   The record states whether a declared floating-point shape reaches the width
   computation in a build where the runtime float width is narrower than the
   hard-coded one, and the basis is something that would fail if the answer were
   different. Reading the call sites does not satisfy this.

2. THE OUTCOME IS MEASURED BEFORE THE CODE IS CHANGED IN RESPONSE.
   The record shows what the unmodified backend does. A measurement taken only
   after a change describes the change.

3. A WRONG WIDTH AND A WRONG ANSWER ARE DISTINGUISHED.
   The record says whether any observable value differs, not only whether a
   computed width differs, and labels the defect latent or live accordingly.

4. IF THE PATH IS UNREACHABLE, THE COMMENT IS STILL CORRECTED.
   Any statement in the source that a floating-point value and a word are the
   same width is either true in every supported configuration or is amended.

5. ANY CODE CHANGE IS JUSTIFIED BY THE MEASUREMENT.
   If a width is threaded through, the record says what the measurement showed
   that made it necessary, rather than that it was convenient.

6. THE PREDICTION IS RESOLVED AGAINST EACH NAMED FALSIFIER.
   The record states, for each, whether it fired, and does not restate the
   prediction to match the result.

7. BOTH FLOAT CONFIGURATIONS ARE REPORTED.
   Package results are given for default features and for the narrow float
   configuration, each with its own figure.

8. NEW OR CHANGED TESTS SURVIVE ORDINARY PARALLELISM.
   Anything added is observed passing under the harness's default threading.

9. NOTHING IS CLAIMED THAT WAS NOT RUN.
   Every count and pass/fail claim corresponds to output appearing in the
   transcript. Carried figures are marked as carried.

10. THE PACKAGE IS GREEN, OR THE RED IS OWNED AND EXPLAINED.
    The native_codegen suite passes, or each failure is named with its cause and
    with a statement of whether the cause belongs to this package.

NOT completion criteria: which branch anything sits on, whether work is
committed, how many commits were made, the order of the ten properties above, or
whether any other goal in the same session advanced.
