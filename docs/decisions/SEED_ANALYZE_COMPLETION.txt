COMPLETION CONDITION — seeding analyze.kel

Ordering is NOT a completion criterion. These properties may be reached in any
order, in any number of commits, on any branch. Judge the end state of the tree,
never the sequence that produced it.

TREE-CHECKABLE END STATE

1. Either analyze.kel is driven by a seed in the Order-1 gate, or a document
   states specifically what blocked it. If it is driven, all of the following
   hold:
     - the stage reaches a verdict rather than exiting early, and the harness
       REQUIRES that rather than assuming it
     - a verdict OBSERVABLY MOVES from what the all-zero buffer already holds,
       and the moved value is not merely non-zero by construction: a subject
       whose bound is zero does not demonstrate the stage computed anything
     - the gate's count of unseeded stages reflects reality

2. Any subject tried and rejected is reported with its cause rather than
   silently replaced.

3. The description of analyze.kel's shared block held anywhere in the tree
   matches the block: every input scalar, every parallel table, and every output
   slot is accounted for, with none omitted. A count stated for these is
   correct.

4. Every census and gate figure quoted as current was re-derived against the
   present tree after the last change capable of moving it. Where a figure
   moved, what moved it is stated.

5. Shared seeding helpers that other stages depend on are either unchanged, or
   those stages' figures are re-derived rather than assumed unchanged.

6. No file under src/selfhost/, and none of src/verify.rs, src/bytecode.rs,
   src/vm.rs, src/wire_schema.rs, or .github/workflows/, differs from the
   v0.2.3 commit the branch has absorbed.

7. Both suites are green, each verified by BOTH cargo's own exit status AND the
   summed per-binary counts, with the two agreeing:
     - the main workspace, run so a failure does not truncate the run
     - native_codegen, which continuous integration does not build and whose
       local run is therefore its only gate
   The two suites are not run concurrently with each other, because the
   workspace carries a wall-clock guard that concurrent load makes fail.

8. The handoff validates against the tree: its ancestry checks pass, and its
   stated suite and census figures match a fresh run.

9. No count is presented as evidence without the command producing it being
   recoverable from the surrounding text.

NOT REQUIRED

- Seeding codegen.kel.
- Declaring the Order-1 gate met; a stage would still be unseeded.
- Resolving the Fixed shared-slot ABI or the float entry ABI; both are held by
  the operator.
- Repairing anything that needs a file this line does not own.
- Any particular branch name, pull request, merge, or commit count.

DISQUALIFYING

- A stage reported as seeded whose observable did not move, or whose run stopped
  early.
- A verdict that moves only because the subject was constructed so that any run
  at all would move it.
- A green reached by narrowing a population, dropping a subject, or relaxing an
  assertion, unless what was excluded is still reported with its cause.
- A guard that cannot fail, or whose ability to fail was never shown.
- A figure carried across a change capable of moving it.
- A suite result read from a pipeline's exit status rather than the command's.
