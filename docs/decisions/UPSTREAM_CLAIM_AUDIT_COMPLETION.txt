COMPLETION CONDITION — the claims about the other line's code

Ordering is NOT a completion criterion. Any order of the work satisfies this, and
nothing here requires a particular branch, commit shape, or process step.

All of the following hold in the tree:

1. EVERY LIVE ACCUSATION IS RESOLVED BY EVIDENCE.
   For each document this line owns that asserts an unrepaired defect in the other
   line's code, the tree records whether that defect currently reproduces, measured
   against the present tree. A claim that no longer reproduces is retracted with
   its date and reason rather than quietly edited.

2. A CONFIRMED-OPEN CLAIM IS WATCHED.
   Each accusation confirmed still open is carried by something that FAILS when the
   defect stops reproducing, with a message saying to retract the claim rather than
   to debug a test. A claim left unwatched is named as unwatched.

3. THE TRIAGE IS RECORDED, NOT JUST ITS RESULT.
   How the candidate set was narrowed -- and by what matcher -- is written down, so
   a later reader can challenge the narrowing rather than inherit it.

4. SELF-VERIFYING CLAIMS ARE IDENTIFIED AS SUCH.
   Where a claim was already carried by a guard that fails on repair, the audit
   says so instead of re-measuring it by hand.

5. THE OWNERSHIP BOUNDARY IS RESPECTED.
   No file under the repository-root src/ or tests/ is modified.

6. NO NEW OPCODE AND NO BYTECODE_VERSION CHANGE.

7. THE BACKEND SUITE IS GREEN IN BOTH FLOAT CONFIGURATIONS, with counts
   re-derived rather than quoted.
