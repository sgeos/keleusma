COMPLETION CONDITION — the Multiword surface

Ordering is not a completion criterion. No property below depends on the order
the work was done in, on which branch it happened on, or on any process step.
Any sequence of actions leaving the tree with these properties is complete.

1. Something in the tree drives multi-word fixed-point programs and compares their
   results against the reference implementation, covering more than one operation
   of that family.

2. At least one limb of at least one subject comes from a runtime parameter rather
   than a literal, so the comparison cannot be satisfied by constant folding, and
   the tree states why that matters.

3. The operation of that family which the backend refuses is pinned with its
   stated cause and with a control showing the refusal is specific to it rather
   than general to the family.

4. The tree carries evidence that the differential detects a fault in the
   multi-word path, meaning a recorded perturbation it fails under. A perturbation
   of scalar arithmetic does not satisfy this.

5. No document in the tree states that the multi-word family is unsupported by the
   backend, and any record of the construction syntax matches what the reference
   accepts.

6. The emitter is unchanged, and nothing describes the refusal as a defect.

7. Any harness newly allocating host buffers for a native call derives its private
   region size from the published contract and is declared wherever the tree
   enumerates such harnesses.

8. src/ and tests/ at the repository root are unchanged by this session except for
   changes the other line itself made.

9. The backend suite passes in both float configurations, and that rests on a
   whole gate run per configuration rather than on separately read phase
   summaries, on targeted runs selected by binary name, or on one run assumed to
   cover both.

10. The handoff state table agrees with the tree, figures that cannot be
    re-derived name the commit they were measured at, and the guards that check it
    pass.

11. The working tree is clean, and the branch on the remote matches the local
    branch, established by querying the remote.
